Plaćanje (Stripe)

Kako član plaća članarinu u aplikaciji, kada se članarina aktivira i kako sve testirati Stripe testnim ključevima.

Zadnja izmjena: 2026-10-14 · simunbarberic

Tok plaćanja

  1. Član na ekranu plana pritisne "Plati". Aplikacija šalje POST /payments sa samo programSlug.
  2. API uzima cijenu iz baze (MembershipProgram.priceCents), sprema Payment sa stanjem PENDING i u Stripeu otvara PaymentIntent. Aplikaciji vraća clientSecret i javni ključ.
  3. Aplikacija otvara Stripeov prozor za plaćanje (PaymentSheet): kartica, Google Pay, a kasnije i Apple Pay. Podaci o kartici idu izravno Stripeu i nikad ne prolaze kroz naš server.
  4. Stripe javlja rezultat na POST /payments/webhook. API provjerava potpis i tek tada aktivira ili produljuje članarinu (O-018).
  5. Aplikacija do 20 s provjerava GET /payments/:id. Kad je stanje SUCCEEDED, osvježi članarinu i QR se pojavi.

Stanja uplate i webhookovi

Stripe događajŠto API napravi
payment_intent.succeededPENDING/FAILED → SUCCEEDED i članarina se produlji. Ako je iznos drugačiji od spremljenog, članarina se ne daje, a greška ide u log da osoblje vrati novac. Stripeu se odgovara 200, jer ponavljanje to ne bi popravilo.
payment_intent.payment_failedPENDING → FAILED. Član može pokušati drugom karticom, a uspjeh i dalje prolazi.
payment_intent.canceled→ CANCELED
charge.refunded (cijeli iznos)→ REFUNDED. Ako je uplata već dala članarinu, oduzme joj se trajanje plana, a ako joj ne ostane vremena, otkazuje se (O-019). Stripe ne jamči redoslijed, pa povrat koji stigne prije uspjeha znači da kasniji uspjeh ne daje ništa.

Svaki događaj obrađuje se točno jednom: njegov id sprema se u StripeEvent u istoj transakciji s promjenom, pa ponovljena dostava ništa ne mijenja. Promjene članarine za istog člana (uplata, povrat, pauza, nastavak) idu jedna po jedna, pod istim zaključanim ključem kao kod ulaza.

Ako član zatvori prozor za plaćanje i ponovno pritisne "Plati" unutar 30 minuta, nastavlja se ista neplaćena uplata umjesto da se otvara nova.

Postavljanje

U apps/api/.env:

VarijablaOdakle
STRIPE_SECRET_KEYStripe Dashboard → Developers → API keys (sk_test_…). Nikad u git ni u aplikaciju.
STRIPE_PUBLISHABLE_KEYIsto mjesto (pk_test_…). API ga šalje aplikaciji.
STRIPE_WEBHOOK_SECRETLokalno: ispis naredbe stripe listen (whsec_…). Na serveru: Dashboard → Webhooks → endpoint https://<api>/payments/webhook.

Bez ovih ključeva API radi normalno, a rute za plaćanje odgovaraju 503 "Plaćanje trenutno nije dostupno".

# Stripe CLI (https://docs.stripe.com/stripe-cli), jednom: stripe login
stripe listen --forward-to localhost:3000/payments/webhook \
  --events payment_intent.succeeded,payment_intent.payment_failed,payment_intent.canceled,charge.refunded
# ispiše whsec_… → STRIPE_WEBHOOK_SECRET, pa ponovno pokreni API
Stripe modul je nativni, pa mobilnu aplikaciju treba jednom ponovno izgraditi: npx expo run:ios --device ili npx expo run:android --device. Stari build nema taj modul i aplikacija s novim kodom na njemu neće raditi.

Testiranje

Bilo koji budući datum isteka, bilo koji CVC. Povrat novca: Stripe Dashboard → Payments → plaćanje → Refund.

Provjereno 2026-10-14 na Stripe test računu, uz prave PaymentIntente i povrate, s webhookovima potpisanim lokalnom testnom tajnom. Prošla je 31 provjera, među njima:

  • iznos se ne može poslati iz aplikacije;
  • prije webhooka nema članarine;
  • bez potpisa ili s krivim potpisom odgovor je 400, a događaj s izmijenjenim iznosom se odbija;
  • ponovljeni webhook ne produljuje članarinu;
  • druga uplata dodaje 365 dana, a povrat ih oduzima;
  • odbijena kartica ostavlja stanje FAILED;
  • tuđe plaćanje vraća 404;
  • povrat jedine uplate otkazuje članarinu i QR;
  • povrat koji stigne prije uspjeha ne daje članarinu;
  • ponovni "Plati" nastavlja istu uplatu;
  • plaćanje tijekom pauze nastavlja članarinu, a nastavak pauze vraća pauzirano vrijeme.

Mobilni dio prolazi provjeru tipova, ali nije isproban na uređaju.

Što još nedostaje

  • Stripe račun teretane za stvarni novac. Mijenjaju se samo ključevi.
  • Apple Pay: merchant ID u Apple Developer računu i merchantIdentifier u pluginu (app.json). Ne radi s besplatnim Apple računom.
  • Računi i fiskalizacija: uz uplatu se još ne izdaje račun, vidi Otvorena pitanja.
  • Cijene u aplikaciji su i dalje upisane u features/home/data/plans.ts. Naplaćuje se cijena iz baze, a Stripeov prozor prikazuje stvarni iznos.
