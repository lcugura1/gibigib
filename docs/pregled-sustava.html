Slojevi API-ja

  • Rute (src/routes/*) su tanke: provjere pristupa i ograničenja zahtjeva u preHandler, Zod validacija tijela, poziv servisa.
  • Servisi (src/services/*) drže svu poslovnu logiku i upite prema bazi.
  • Pluginovi (src/plugins/*): jwt.ts za članove, device-auth.ts za uređaje, rate-limit.ts za ograničenje broja zahtjeva.
  • Greške se bacaju kao HttpError(status, poruka) i oblikuju u src/middleware/error-handler.ts.
  • Konfiguracija se validira u src/config/env.ts; API se ne pokreće ako nešto nedostaje ili je neispravno.

Ulaz u teretanu

  1. Aplikacija svakih 15 s traži GET /entry/token. Server vraća postojeći neiskorišteni token ako vrijedi još barem 20 s, inače stvara novi koji vrijedi 45 s.
  2. Skener pročita QR i pošalje POST /entry/scan sa svojim ključem.
  3. Server provjeri token (postoji, nije iskorišten, nije istekao) i članarinu (aktivna, nije pauzirana).
  4. U jednoj transakciji, zaključanoj po članu: provjera anti-passbacka (zadnji odobreni ulaz unutar ENTRY_ANTI_PASSBACK_MINUTES), trošenje tokena uvjetnim upisom, prvi dolazak u danu, zapis GRANTED i naredba za vrata.
  5. Svako odbijanje zapisuje se u EntryEvent s razlogom.
  6. Kontroler vrata anketira GET /device/commands svojim ključem i jednom dobije open.

Kod: apps/api/src/services/entry.ts, services/door.ts, plugins/device-auth.ts; aplikacija apps/mobile/features/home/hooks/use-entry-token.ts.

Zaboravljena lozinka

  1. POST /auth/forgot-password uvijek odgovara isto: "Ako račun postoji, poslali smo upute na e-adresu".
  2. Ako račun postoji i u zadnjih 60 s nije poslan kod, server generira 6-znamenkasti kod (vrijedi 15 min, u bazi samo hash) i šalje ga e-mailom u pozadini.
  3. POST /auth/reset-password prije usporedbe "potroši" jedan od 5 pokušaja. Nakon petog kod se briše.
  4. Uspješan reset mijenja lozinku i briše sve sesije člana.

Kod: apps/api/src/services/auth.ts, services/email.ts.
